# 双语试听视频：字幕、组装与换轨检查
# Bilingual preview video: subtitles, assembly and audio revisions

这份说明接在[旋律与人声工作流](README.md)之后，关注音频候选如何变成可审查的双语试听视频，以及换音轨时哪些内容要一起更新。

**本文是通用操作指南。** 当前 Python 模块仍只提供 README 列出的音频处理能力，没有新增字幕生成、视频渲染或自动混音命令。本文不附作品素材、真实唱词、录音、时间码或制作记录，也不宣称任何试听成品已经通过听审。

## 1. 先确定本轮使用的版本

在动字幕或画面前，明确本轮采用的文字、干声、伴奏、混音和画面版本。保留原件，候选版另存；不同用途的版本可以并存。

用最终混音的时间轴作为视频同步基准，并记录：
- 起始偏移、开头与结尾的静音，以及预期片尾长度；
- 哪些段落使用了哪个音轨版本；
- 当前字幕、画面和混音分别对应哪个版本；
- 已确认的内容、仍待试听的内容，以及本轮修改范围。

不要仅凭文件名中的“final”判断版本，也不要在换人声后沿用未经检查的旧字幕或混音控制点。

## 2. 双语字幕分别承担什么作用

**原语言字幕对应实际发声内容，译文负责释义。** 两者都应从经过确认的文字出发，不能用识别结果悄悄替换原文。发现文字和声音不一致时，先标出差异，再决定改文字还是改音频。

制作每条字幕时：
1. 给字幕事件一个稳定编号，分别记录原文、译文、开始和结束位置。重复段落也要有独立事件，避免只改第一次出现的位置。
2. 根据当前声音核对边界，尤其是字头、拖长元音、停顿和尾音。总句长相同，不代表句内节奏相同。
3. 自动转写或对齐只提供时间候选。低置信片段、零时长事件和无声区需要人工检查，不能直接当作正确边界。
4. 检查起止顺序、是否超出成片范围及是否意外重叠。需要同时显示的双语行或注音应按设计共同排版。
5. 原文或重复次数变化时，同时检查译文、注音和对应画面。译文改写应保留原意，不增添声音里没有的承诺或情节。

注音与翻译是不同层。注音要对应正确的字词，特别检查小字号、组合字符、长音和换行后的对应关系。

## 3. 从字幕和画面组装视频

先选择交付形式：
- **烧录字幕**：文字成为画面的一部分，播放方式稳定，但修改后必须重新渲染视频。
- **可切换字幕轨或外挂字幕**：便于修改和选择语言，但目标播放器未必支持全部字体、排版或注音。必要时另做有烧录字幕的审阅版。

FFmpeg 可以承担画面串接、字幕渲染和音视频封装；这里不提供已集成的渲染脚本。使用前应检查自己的 FFmpeg 构建、字幕支持和字体覆盖，软件与字体许可分别处理。

组装时按以下顺序核对：
1. 确认画布尺寸、画面顺序、每张文字卡的显示长度和安全边距。
2. 先渲染最容易出问题的一小段，例如双语长句、注音、重复段或片尾。
3. 实际看导出画面，检查缺字、错字、字体替换、换行、注音错位和遮挡。只看字幕源文件不能证明画面正确。
4. 在预期观看尺寸下检查可读性，包括手机上的小画面；避免只在编辑器放大视图中验收。
5. 明确选择要写入的视频、音频与字幕轨，检查语言标记和默认播放轨，避免把旧混音一起带入。
6. 核对开头、每个切换点和完整结尾。不要仅靠“取最短流”结束导出，否则可能截掉尾音、片尾卡或字幕。
7. 片尾只列实际使用的工具和适当的合成说明。未运行的技术不要写成已使用。

封面与文字卡的呈现不能直接算作角色演唱、口型同步或动画已经完成。

## 4. 换音轨时，按影响范围一起更新

保留干声、伴奏和混音三个层次。局部改句可以从可编辑音轨重新混合，不必从压缩成片反复拆解。

| 修改情况 | 至少需要重新检查 |
| --- | --- |
| 只换声音，总时长未变 | 句内字头与尾音、字幕边界、局部响度、伴奏遮挡及接缝 |
| 句内节奏改变，句长未变 | 每个主要发声事件、注音或逐字效果、伴奏避让控制点 |
| 某句长度或停顿改变 | 后续字幕、画面切换、伴奏节拍、淡入淡出和片尾位置 |
| 文字或重复次数改变 | 原文、译文、注音、重复事件数量和画面顺序 |
| 只改伴奏或混音 | 人声可懂度、控制窗口、开头结尾、输出轨和音画同步 |

伴奏的分段增益、侧链压低或其他动态处理，应对照新的人声活动范围重新检查。旧控制窗口可能在错误的字头压低伴奏，也可能错过新延长的尾音。

修订前后先比相同时间基准上的未压缩音频：
- 局部替换应检查修改窗口内、边界附近和未修改区。
- 只有采样率、声道、时间对齐及处理链一致时，逐采样一致性才有明确意义。
- 若混响尾部、动态处理或总线处理会影响窗口外，应记录合理的影响范围；不要要求本来会改变的区域必须逐采样相同。
- 有损音视频重新编码可能改变解码波形，不能把其逐采样差异直接当成修改越界。保留编码前的比较依据，再检查导出后的同步和听感。

## 5. 分层验收，不合并成一个“通过”

| 层次 | 核对内容 |
| --- | --- |
| 文件与封装 | 能完整解码；时长、分辨率、声道、音轨和字幕轨符合本轮要求 |
| 文字与视觉 | 原文、译文、注音、重复次数及画面顺序一致；无缺字或遮挡 |
| 时间同步 | 开头、句内事件、换页、停顿、尾音和片尾均对齐当前混音 |
| 试听 | 发音、内部节奏、接缝、音色和伴奏遮挡经过实际聆听 |
| 发布 | 来源、许可、署名、隐私范围及具体公开内容得到确认 |

每层分别记“已检查”“待检查”或“不适用”，并简述依据。文件能播放、数值无削波或转写结果相近，都不能替代听审；没有听过就保持待检查。

建议先审修改段及其前后衔接，再完整播放最终导出一遍。仅检查几个截图不足以确认整段视频与音轨一致。

## 6. 留一份简短的版本清单

清单放在自己的工作目录中，不默认提交公开仓库。每个候选至少写清：
- 候选版本及用途；
- 输入版本和输出文件；
- 修改的片段及原因；
- 被联动更新的字幕、画面、伴奏或混音；
- 已完成和未完成的检查；
- 已知限制，以及需要时回退到哪个版本。

可在私人归档中保留文件校验值用于核对传输是否完整，但不要把作品文件散列、源目录或其他可关联私人素材的标识放入公开示例。

## 7. 公开分享前的最后一步

公开教程只保留通用方法。需要演示时，重新创作独立的文字、旋律、声音和画面，并明确哪些只是示意。不要把私人工程整包上传，也不要只替换名称就复用原作品。

发布前执行现有的[隐私检查清单](PRIVACY_CHECKLIST.md)，并参考[依赖与资产边界](THIRD_PARTY.md)。还要检查字幕、封面、片尾、缩略图、嵌入标签和导出元数据；工具许可、模型条款、声音同意和作品权利分别核对。“技术演示”或“非盈利”标签不能代替使用许可。

## English summary

This companion guide covers bilingual subtitles, preview-video assembly and the checks that must follow an audio revision. Use a reviewed mix as the timing reference; keep source-language text, translation, pronunciation annotations and repeated cues in sync. Inspect rendered text in the actual output, verify track selection and the complete ending, and recheck music automation whenever vocal timing changes.

Keep dry voice, backing and mixes separate. Compare unchanged regions before lossy encoding under matching conditions, accounting for effects that extend beyond an edit. Track file checks, visual checks, synchronization, listening and publication separately. This is documentation, not a newly implemented video pipeline or a claim of listening approval; no production media or identifying examples are included.
